# 竞赛副本闯关

> 一个把「项目答辩制竞赛」变成游戏闯关的在线工具，帮大学生理清一场比赛到底要做什么、怎么一步步准备、自己还缺什么。

在线地址：**https://comp.niry.cn**

---

## 这是什么

很多大学生面对「创新创业大赛」「商业挑战赛」这类需要答辩、路演、提交作品的项目制竞赛，最头疼的不是不会做，而是**看不懂规则、不知道从哪下手、不知道要准备哪些材料、不知道什么时候该交什么**。

这个工具把一场比赛拆成一关一关的「副本」：先了解你的情况 → 联网查到这场比赛的**真实情报** → 帮你做一次「装备测评」（你现在的身份/专业/时间够不够用）→ 给出过来人经验 → 再把它拆成一步步可以执行的**任务清单和计划表**。

核心一句话：**求人不如求己，先把这场比赛的规则和步骤，一条条理清楚。**

---

## 主要功能

| 功能 | 说明 |
|------|------|
| 🎯 识别比赛 | 输入比赛名字（哪怕模糊，比如「商挑赛」），实时联网搜索，列出「可能是哪几个比赛」让你确认，并附「查看来源」可点开原文核对 |
| 📋 副本情报 | 针对你确认的比赛，整理出主办方、赛制、参赛对象、报名入口、赛道、时间、环节等结构化信息 |
| 🛡️ 装备测评 | 结合你填的学历/专业/时间，判断你和这场比赛的匹配度，并给出针对性建议 |
| 💡 过来人经验 | 针对**这场比赛**给出经验与避坑点（不再是一套通用套话） |
| 🗺️ 关卡地图 | 把比赛流程拆成可点选的关卡 |
| ✅ 任务与计划表 | 每一关给出「具体要做什么、要交什么」，并生成可执行的计划表 |
| ⚡ 实时联网搜索 | 所有内容基于当下真实的搜索结果，不是写死的旧信息 |

## 技术架构

```
┌─────────────┐        ┌──────────────────────┐        ┌──────────────┐
│  前端页面     │  ───▶  │  Cloudflare Worker    │  ───▶  │  百度 AI 搜索  │
│  (单文件 HTML) │        │  (静态资源 + 后端 API)  │        │  (实时联网搜索) │
└─────────────┘        └──────────────────────┘        └──────────────┘
                              │
                              ▼
                        ┌──────────────┐
                        │  LLM 整理情报  │
                        │ (WorkBuddy 云) │
                        └──────────────┘
```

- **前端**：单个 `index.html`（原生 HTML/CSS/JS，无框架），游戏化像素风界面。
- **搜索后端**：`worker.js`，一个 Cloudflare Worker 同时托管静态页面和处理 `/api/search` 接口。
- **联网搜索**：百度 AI 搜索（`baidu_search_v2`），返回标题、摘要、来源、时间。
- **情报整理**：由 LLM 把搜索结果整理成结构化信息，并在后台逐步深化。

## 部署

本项目的线上架构是「**单个 Cloudflare Worker + 自定义域名（custom domain）**」，静态页面和搜索 API 都走同一个 Worker。

> ⚠️ 详细的分步图文教程见 [`docs/部署到Cloudflare.md`](docs/部署到Cloudflare.md)。

简要步骤：

1. 申请百度 AI 搜索的 API Key（见 [`docs/申请搜索Key.md`](docs/申请搜索Key.md)）。
2. 用 `wrangler` 配置 secret（密钥不进代码库）：

   ```bash
   wrangler secret put BAIDU_API_KEY
   ```

3. 部署：

   ```bash
   wrangler deploy
   ```

4. 绑定自定义域名（在 `wrangler.toml` 的 `[[routes]]` 里配 `custom_domain = true`）。

### 一个关键坑（已踩过）

早期用「`routes` + `assets`」的组合方式部署时，会出现**静态页面能打开、但 `/api/*` 接口返回 522** 的问题——因为静态资源走 Cloudflare 的 Assets 平台，而 Worker 代码没被正确路由。正确做法是改用 **custom domain** 绑定整个 Worker。详见 CHANGELOG 和部署文档。

## 本地开发（可选）

线上走 Worker，本地如果想单独跑后端调试：

```bash
npm install
npm start        # 启动 server.js，本地 http://localhost:3000
```

> 注意：`server.js` 是开发期用的 Node 后端，生产环境不依赖它。它的百度 key 从环境变量 `BAIDU_API_KEY` 读取，不要硬编码。

## 关于信息准确性

本工具的核心原则是**不编造**：

- 所有比赛信息来自实时联网搜索，信息不足的字段会如实标注「未核实」。
- 竞赛规则、时间、报名方式随时会变，请以官方通知为准。
- 工具给出的「经验」「建议」仅供参考，不构成对任何比赛结果的承诺。
